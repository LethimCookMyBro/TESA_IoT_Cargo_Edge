## Abstract

This paper presents an embedded system mounted on reusable packages to classify package events such as being handled by a forklift or transported in a truck. The system uses accelerometer data and a one-dimensional convolutional neural network (1D CNN) running locally on an IoT device.

The work addresses three constraints:

1. The dataset is imbalanced and contains multiple time-series classes.
2. The device must remain asleep most of the time to achieve a multi-year battery life.
3. The neural network must be small enough for a microcontroller.

The proposed pipeline tests SMOTE and ADASYN for data augmentation, then applies pruning, INT8 quantization, and Huffman coding for model compression. In the reported two-class result, the compressed model reaches:

- Forklift precision: **94.54%**
- Truck precision: **95.83%**
- Model size: **14 kB**, more than four times smaller than the original 51 kB model
- Inference power: **316 mW**
- Inference duration: **27 ms**

## Keywords

Deep learning; embedded systems; classification; low-energy consumption; accelerometer data; TinyML.

## 1. Introduction

Reusable plastic crates can replace disposable cardboard packaging and reduce environmental impact. Monitoring package events helps identify loss, damage, theft, and responsibility during the logistics lifecycle.

Possible tracking technologies include:

- GPS — inaccurate indoors or in harsh environments
- TDoA — requires a dense network of antennas and IoT devices
- BLE — short range and requires infrastructure at each monitored site

Instead of continuously tracking a package, the proposed approach identifies important events from accelerometer signals. The detected event can trigger later actions such as network communication.

TinyML is used because it enables:

- Low energy consumption
- Low inference latency
- Local processing without sending raw data to a server
- Better privacy and security because data can stay on the device

The device wakes only when motion occurs, classifies the event quickly, and returns to low-power sleep mode.

## 2. Main contributions

1. Adapt SMOTE and ADASYN to preserve continuity in accelerometer time-series data.
2. Use a 1D CNN with a confidence threshold. Predictions below the threshold are assigned to a special `Dummy` class.
3. Apply pruning, quantization, and entropy coding to reduce the model footprint for an ESP32 microcontroller.
4. Deploy and measure the model on the embedded device.

## 3. Methodology

### 3.1 Dataset and `Dummy` class

The `Dummy` class represents irrelevant or uncertain movements, for example:

- A package being moved manually
- A package being opened
- A package falling to the ground
- Samples that do not meet the confidence threshold
- Misclassified samples

Using `Dummy` prevents the device from treating every movement as a meaningful logistics event. It reduces unnecessary follow-up processing and helps limit cascading errors.

### 3.2 CNN architecture

The model consists of 1D convolutional layers followed by:

1. Batch normalization
2. ReLU activation
3. Further convolutional processing
4. Softmax output

The input has dimensions:

```text
(V_l, l_axes)
```

where:

- `V_l` is the time-window length in samples
- `l_axes` is the number of accelerometer axes

The output contains the target event classes plus the `Dummy` class.

### 3.3 Confidence threshold

Let the model output probabilities for all classes. If the highest probability is above a selected threshold, the corresponding class is returned. Otherwise, the event is classified as `Dummy`.

This allows the system designer to trade recall for precision. A higher threshold usually avoids incorrect actions but may send more samples to the `Dummy` path.

Accuracy is not suitable as the main metric because the dataset is strongly imbalanced. Precision-recall curves are used to select thresholds for each class.

### 3.4 Data augmentation

#### SMOTE

SMOTE creates a synthetic minority sample by interpolating between a selected minority vector and one of its nearest neighbors:

```text
x_new = x_selected + α × (x_neighbor − x_selected)
```

where `α` is randomly selected from `[0, 1]`.

For time-series data, the interpolation must preserve the continuity of the accelerometer vector.

#### ADASYN

ADASYN generates more synthetic data near difficult decision boundaries. For each minority sample, the difficult-sample ratio is based on the number of majority-class neighbors:

```text
r_i = Δ / K
```

The normalized ratio determines how many synthetic samples are generated. The total number of generated samples is controlled by:

```text
G = (m_l − m_s) × β
```

where:

- `m_l` is the majority-class size
- `m_s` is the minority-class size
- `β ∈ [0, 1]` controls the desired balance

### 3.5 Model compression

The compression pipeline is:

```text
PyTorch model → ONNX → TensorFlow Lite → C/C++ source → ESP32
```

It uses:

- **Pruning:** remove low-magnitude weights using L1-norm unstructured pruning
- **Weight rewinding:** retrain the remaining weights after pruning
- **INT8 quantization:** convert weights, biases, and activations from floating point to 8-bit integers
- **Entropy encoding:** use Huffman coding to store frequent values efficiently

The INT8 converter uses 100 randomly selected representative samples to calibrate value ranges.

## 4. Experiment

### 4.1 Dataset collection

Four ultra-low-power IoT devices with MEMS accelerometers were placed in a reusable package at a logistics training facility.

The classes were:

- **Forklift:** package transported or lifted by a forklift
- **Truck:** package placed in the back of a truck, moving or idle
- **Dummy:** other movements, irrelevant events, low-confidence samples, and misclassifications

Dataset size:

| Class | Samples |
|---|---:|
| Forklift | 382,000 |
| Truck | 2,520,000 |
| Dummy | 9,912 |

Sampling frequency: **20 Hz** from a tri-axial accelerometer.

The dataset is proprietary and is not publicly available.

### 4.2 Augmentation configuration

- Number of nearest neighbors: `5`
- ADASYN `β`: `0.4`
- SMOTE was adjusted to generate the same number of samples as ADASYN

ADASYN performed better because it concentrates samples near difficult class boundaries.

### 4.3 Augmentation results

| Dataset | Forklift precision | Forklift recall | Truck precision | Truck recall |
|---|---:|---:|---:|---:|
| Original | 82.17% | 83.21% | 91.56% | 59.98% |
| SMOTE | 97.95% | 89.11% | 94.86% | 92.38% |
| ADASYN | **98.05%** | **91.17%** | **95.75%** | **96.62%** |

ADASYN was selected for the remaining experiments.

### 4.4 Training configuration

- Framework: PyTorch
- GPU: NVIDIA RTX 3080
- Split: 70% training, 30% validation/testing
- Epochs: 20
- Batch size: 200
- Optimizer: Stochastic Gradient Descent
- Learning rate: 0.5
- Momentum: 0.9
- Weight decay: `2e-5`
- Label smoothing: 0.1
- Class weights: used in the loss function
- Learning-rate scheduler: used

### 4.5 Compression results

| Configuration | Model size | Forklift precision | Forklift recall | Truck precision | Truck recall |
|---|---:|---:|---:|---:|---:|
| Original | 51 kB | 98.05% | 91.17% | 95.75% | 96.62% |
| Pruning | 33 kB | 93.61% | 96.12% | 95.72% | 93.85% |
| Pruning + quantization | **14 kB** | 94.54% | 92.59% | **95.83%** | 88.66% |

The selected pruning ratio was 50%. Pruning alone reduced the size by approximately 1.5×. Adding quantization reduced the model to 14 kB, while maintaining high precision.

### 4.6 Deployment

The TFLite model was converted to a C/C++ source file because the microcontroller does not natively execute the TFLite format.

Target platform:

- ESP32 microcontroller
- Espressif IoT Development Framework (ESP-IDF)

Although the ESP32 module has 16 MB of flash, that memory is shared with other components such as Wi-Fi and Bluetooth. The compressed model can also fit entirely in SRAM, reducing memory-access overhead.

### 4.7 Energy consumption

- Power during inference: **316 mW**
- Inference duration: **27 ms**
- Baseline device power: **300 mW**

The additional power used during inference is small compared with baseline consumption. Minimizing wake time remains the key factor for long battery life.

## 5. Conclusion and future work

The study demonstrates that a compact 1D CNN can classify package-handling events directly on an ESP32 using accelerometer data. The combination of ADASYN, confidence thresholding, pruning, quantization, and Huffman coding enables deployment under embedded memory and energy constraints.

Main reported results:

- 14 kB compressed model
- Forklift precision: 94.54%
- Truck precision: 95.83%
- 316 mW during inference
- 27 ms inference duration

Future work:

- Add multimodal sensor fusion
- Include additional sensors
- Train with more unsupervised data, which is easier to collect in logistics environments

## 6. Practical takeaway for an Edge AI / IoT project

The paper's most reusable design pattern is:

```text
Wake on motion
    ↓
Collect a short accelerometer window
    ↓
Run a small CNN locally
    ↓
Apply a confidence threshold
    ├─ High confidence → trigger an action or transmit an event
    └─ Low confidence  → classify as Dummy / ignore / verify cheaply
    ↓
Return to low-power sleep
```

For a prototype, the important lessons are:

1. Optimize precision and recall separately when classes are imbalanced.
2. Add an uncertainty or `Dummy` class instead of forcing every sample into a meaningful class.
3. Measure wake time and inference energy, not just model accuracy.
4. Compress the model only after validating the uncompressed baseline.
5. Keep the full pipeline in mind: sensor → preprocessing → model → threshold → action.
