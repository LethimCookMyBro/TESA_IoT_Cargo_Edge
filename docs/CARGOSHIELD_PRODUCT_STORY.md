# CargoShield AI — Product Story

> **CargoShield AI**
> ระบบปกป้องสินค้าเปราะบางสำหรับหุ่นยนต์ขนส่ง

เอกสารนี้ใช้สำหรับทำโปสเตอร์ เตรียมการนำเสนอ และตอบคำถามกรรมการ
ทุกข้อความในนี้ตรวจสอบได้จาก repository และหลักฐานใน `reports/`

---

## 1. ปัญหาที่แก้

สินค้าเปราะบาง — ขวดแก้ว อุปกรณ์อิเล็กทรอนิกส์ ตัวอย่างทางการแพทย์ — เสียหายระหว่างขนส่งในคลังสินค้า
โดยที่ไม่มีใครรู้ว่าเสียหายตอนไหน

สาเหตุที่พบบ่อย:

- **พื้นต่างชนิดสั่นไม่เท่ากัน** พื้นปูพรม พื้นคอนกรีตหยาบ และรอยต่อกระเบื้องสร้างแรงสั่นคนละระดับ
- **หุ่นยนต์วิ่งความเร็วเดียวตลอดเส้นทาง** ไม่ว่าจะขนอะไรอยู่ และไม่ว่าพื้นตรงนั้นจะแย่แค่ไหน
- **ความเสียหายมารู้ตอนปลายทาง** ไม่มีหลักฐานว่าเกิดที่โซนไหน จึงแก้ที่ต้นเหตุไม่ได้
- **ระบบอัตโนมัติที่ "เดา" อันตรายกว่าระบบที่ยอมหยุด** เมื่อโมเดลไม่มั่นใจแต่ยังวิ่งต่อ

## 2. One-line pitch

> **AI วิเคราะห์แรงสั่นสะเทือนระหว่างขนส่ง แล้วปรับความเร็ว เลือกเส้นทาง และ Safe Stop เมื่อพบความเสี่ยงต่อสินค้า**

## 3. ระบบทำงานอย่างไร (5 ขั้น)

| ขั้น | เกิดอะไรขึ้น | ใครทำ |
| --- | --- | --- |
| 1 | รับหน้าต่างข้อมูล IMU 128 × 6 (ตอนนี้มาจาก Dataset Replay) | `cargo.sources` |
| 2 | สกัด 48 features แล้วให้โมเดลจำแนกพื้นผิว + ให้คะแนนความเสี่ยงแรงสั่น | `cargo.inference` |
| 3 | **Safety Core** ตัดสินใจแบบ deterministic จากประเภทสินค้า + ความเสี่ยง + ความมั่นใจ + สิ่งกีดขวาง | `cargo.decision_engine` |
| 4 | สั่ง `MOVE` / `SLOW_DOWN` / `HOLD_UNCERTAIN` / `SAFE_STOP` พร้อมอัตราความเร็ว และจำความเสี่ยงรายโซนไว้วางเส้นทางรอบหน้า | `cargo.controller`, `cargo.risk_map`, `cargo.routing` |
| 5 | เผยแพร่สถานะผ่าน MQTT ให้หน้าจอ 3 มิติ และบันทึกลง Historian ให้ Fleet Guardian วิเคราะห์ย้อนหลัง | `cargo.mqtt_service`, `cargo.historian` |

**นโยบายความเร็วตามประเภทสินค้า** (`cargo/decision_engine.py`):

| ความเสี่ยงแรงสั่น | สินค้าทั่วไป | สินค้าเปราะบาง |
| --- | --- | --- |
| low | 100% | 80% |
| medium | 75% | 45% |
| high | 50% | 25% |

สินค้าเปราะบางเดินทางช้ากว่าเสมอที่ความเสี่ยงเท่ากัน — นี่คือหัวใจของผลิตภัณฑ์

หน้าเว็บ ฐานข้อมูล และ Maintenance Copilot **สั่งหุ่นยนต์ไม่ได้** และทำให้การตัดสินใจช้าลงไม่ได้
ถ้า PostgreSQL ล่ม หรือหน้าเว็บปิด Safety Core ยังทำงานครบ — พิสูจน์ใน `scripts/fleet_scenario.py`

## 6. สิ่งที่กรรมการควรสังเกต

1. **หน้าแรกตอบได้ใน 5 วินาที** — ขนอะไร เสี่ยงแค่ไหน AI สั่งอะไร ใช้ความเร็วเท่าไร
2. **สินค้าเปราะบางถูกปฏิบัติต่างจริง** สลับประเภทสินค้าแล้ว speed ratio เปลี่ยนทันที
3. **ระบบยอมหยุดเมื่อไม่มั่นใจ** `HOLD_UNCERTAIN` ไม่ใช่ bug แต่เป็น feature
4. **Safe Stop ล็อก** ต้องมีคนกดปลด ไม่มี auto-clear
5. **ป้ายที่มาของข้อมูลอยู่ตลอดเวลา** ไม่มีการแอบอ้างว่าเป็นฮาร์ดแวร์
6. **หน้าเว็บไม่เคยตัดสินใจเอง** ทุกค่ามาจาก MQTT ที่ Python เผยแพร่
7. **Maintenance Copilot อ่านได้อย่างเดียว** บังคับด้วย PostgreSQL role ไม่ใช่ด้วยคำสัญญา

## 7. สิ่งที่ทำงานจริง (ตรวจสอบได้)

- โมเดล RandomForest จำแนกพื้นผิว 9 คลาสจาก 48 features บนหน้าต่าง IMU 128 × 6 จริง
- Confidence threshold 0.55 เลือกจาก validation split ที่ group-disjoint (`training/select_confidence.py`)
- Safety Core แบบ deterministic ที่ทดสอบครบทุกสาขา (`cargo/decision_engine.py`)
- Cargo-aware speed policy และ Route Risk Memory ที่เปลี่ยนเส้นทางจริงเมื่อโซนเสี่ยงสะสม
- สัญญา MQTT แยกตามหุ่นยนต์ พร้อม sequence gate กันข้อมูลซ้ำ/ลำดับผิด
- Health monitor ตรวจค่า NaN, ค่าเกินพิสัย, ค่าค้าง, ค่ากระโดด และ sensor disagreement
- PostgreSQL Historian ผ่าน queue ที่ทิ้งข้อมูลแทนการบล็อก Safety Core
- History API แบบ GET-only และ read-only maintenance boundary
- หน้าเว็บ Three.js ที่แสดงสถานะจาก MQTT และมี no-WebGL fallback ครบ

## 8. สิ่งที่เป็น Simulation หรือ Dataset

**ทุก record ในระบบนี้เป็น `DATASET` หรือ `SIMULATED` — ไม่มี `HARDWARE` แม้แต่แถวเดียว**

- หน้าต่าง IMU มาจากชุดข้อมูล CareerCon ที่บันทึกไว้ (validation split) ไม่ใช่การวัดสด
- ระยะสิ่งกีดขวางเป็น **ค่าที่ผู้ควบคุมป้อน** ไม่มีเซ็นเซอร์วัดระยะจริง
- โซน A1–C2 ตำแหน่ง และการเคลื่อนที่ในภาพ 3 มิติ เป็นการสาธิต ไม่ใช่ localization
- ช่องสัญญาณเซ็นเซอร์ของหุ่นยนต์หลายตัวใน Fleet Guardian สังเคราะห์ขึ้นตามหน่วยในแคตตาล็อก
- ตัวเลข latency เป็นของ simulator บนเครื่องพัฒนา ไม่ใช่ประสิทธิภาพของบอร์ด
- **Dataset Replay เป็นวิธีสาธิตเมื่อยังไม่มีฮาร์ดแวร์ ไม่ใช่ความสามารถหลักของผลิตภัณฑ์**

## 9. Future Hardware

ยังไม่เปิด live BMI270 inference โดยตั้งใจ — ไม่ทำ stub ที่ทำให้เข้าใจผิดว่ารองรับแล้ว
ก่อนเปิดต้องมีหลักฐานครบ:

1. Calibration ของ BMI270 และหน่วยที่ตรงกับแคตตาล็อกใน `cargo/health.py`
2. Sampling rate และ timestamp ที่เข้ากันได้กับหน้าต่าง 128 ตัวอย่าง
3. เซ็นเซอร์วัดระยะจริงมาแทนค่าที่ผู้ควบคุมป้อน พร้อม calibrate ระยะหยุด
4. Localization จริงก่อนจะอ้างตำแหน่งใด ๆ
5. หลักฐาน pinout/connector ก่อนต่อโมดูลเสริม (`docs/HARDWARE_EXPANSION_MATRIX.md`)

เส้นทางเชื่อมต่อเตรียมไว้แล้ว: ตัวอย่างจากบอร์ดจะเข้าทาง fleet telemetry contract
(`cargo/contracts.py`) และถูกตรวจโดย `cargo/health.py` ด้วย provenance `HARDWARE`

## 10. Maintenance Copilot story

**ปัญหา:** เมื่อหุ่นยนต์ Safe Stop ช่างต้องไล่อ่าน log หลายที่กว่าจะรู้ว่าเกิดอะไร

**ทางแก้:** `Maintenance Assistant` ใน Fleet Guardian ตอบ 7 คำถามที่กำหนดไว้ล่วงหน้า
โดยแนบแถวหลักฐานจากฐานข้อมูลมาด้วยเสมอ:

1. ทำไมหุ่นยนต์ตัวนี้ Safe Stop หรือเสื่อมสภาพ?
2. หุ่นยนต์ตัวไหนควรตรวจสภาพ?
3. โซนไหนมีแรงสั่นสะสมสูงที่สุด?
4. สรุปเหตุการณ์ของกะนี้
5. สร้าง maintenance checklist (ฉบับร่างให้มนุษย์ตรวจ)
6. แสดงหลักฐานเซ็นเซอร์รอบเหตุการณ์
7. ช่วงข้อมูลใดเหมาะกับการ export ไปตรวจหรือ train รอบใหม่?

**ขอบเขตที่บังคับด้วยระบบ ไม่ใช่ด้วยคำสัญญา:**

| กลไก | อยู่ที่ไหน |
| --- | --- |
| PostgreSQL role ที่มีแค่ `SELECT` | `cargo/db.py::ensure_readonly_role` |
| ไม่มี MQTT client / publisher ในโมดูล | `cargo/maintenance.py` |
| ทุก SQL ในโมดูลเป็น `SELECT` (ตรวจด้วย `ast` ไม่ใช่ grep) | `tests/test_fleet_historian.py` |
| API เป็น GET-only ทุก verb อื่นตอบ 405 | `cargo/history_api.py` |
| คำถามเป็น allowlist ถามนอกรายการไม่มี endpoint | `history_api.COPILOT_QUESTIONS` |
| ไม่มีช่องพิมพ์อิสระในหน้าเว็บ | `webapp/fleet.html` |

**Copilot ทำไม่ได้:** สั่งมอเตอร์ · publish MQTT · ปลด Safe Stop · เปลี่ยน threshold ·
เปลี่ยนเส้นทาง · แก้ฐานข้อมูล · retrain/deploy โมเดล · รับทราบงานบำรุงรักษาแทนคน

**สถานะ Hermes ปัจจุบัน:** ยังไม่เชื่อมต่อ หน้าเว็บแสดง `Hermes provider: Not connected` ตามความจริง
คำตอบทั้งหมดมาจาก SQL แบบ deterministic ไม่มีโมเดลภาษาอยู่ในเส้นทางนี้
วิธีต่อ Hermes ภายหลังอยู่ใน `docs/HERMES_MAINTENANCE_COPILOT.md`

**Latency ไม่อยู่ใน safety path** กว่าจะมีใครอ่าน boundary นี้ Safety Core ตัดสินใจและลงมือไปแล้ว
